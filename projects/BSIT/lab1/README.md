# Лабораторная работа 1. Распределённая система сбора информации

Агент (сервер) на портах завершения Win32 + консольный клиент. Шифрование через CryptoAPI.

## Файлы

| Файл | Назначение |
|---|---|
| `server.c` | Сервер (агент): IOCP, AcceptEx, пул потоков, автомат состояний подключения |
| `sysinfo.c` | Разбор запросов и сбор информации (ОС, время, память, диски, ACL, владелец) |
| `client.c` | Клиент: меню, запрос, форматированный вывод |
| `common.c/.h` | Общее: формат записей, UTF-8, консоль, CryptoAPI, кадры |
| `build.bat` / `build_mingw.bat` | Сборка (MSVC / MinGW-w64) |

## Сборка и запуск

MSVC: открыть «x64 Native Tools Command Prompt», выполнить `build.bat`. MinGW: `build_mingw.bat`.

```
server.exe [порт]      (по умолчанию 9000, Ctrl+C - выход)
client.exe
```

Для доступа с других компьютеров на машине с агентом нужно разрешить входящие TCP на порт 9000 в брандмауэре.
Для чтения прав доступа и владельца чужих объектов агент нужно запускать от имени администратора.
Собирайте x64-версию на x64-системе: 32-битный процесс видит реестр через WOW64-перенаправление.

## Архитектура и её обоснование

* **Кто инициирует передачу - клиент.** Центральный компьютер сам опрашивает агентов: он знает, когда ему нужны данные,
  и сам решает, к каким машинам обращаться. Агентам не нужно знать адрес центра и держать очередь недоставленных данных.
* **Постоянно работает - сервер (агент).** Он запускается на каждом опрашиваемом компьютере и всегда готов принять запрос.
  Клиент запускается на центральном компьютере только на время опроса.
* **Сервер stateless.** Каждый запрос самодостаточен: одно подключение - один запрос - один ответ, никакой информации
  между запросами агент не хранит. Это упрощает агент, снимает проблемы с обрывом сессий и перезапуском,
  позволяет клиенту обращаться к любому экземпляру. На время одного подключения хранится только сеансовый ключ шифрования.
  Дорогая операция (генерация RSA-пары) выполняется клиентом один раз при запуске и повторно используется для всех подключений.

## Прикладной протокол

Транспорт: TCP, порт 9000. Каждое сообщение - **кадр**: 4 байта длины (big endian) + тело.

### Рукопожатие (на каждое подключение)

1. Клиент -> сервер: публичный RSA-2048 ключ клиента (`PUBLICKEYBLOB`), открытым текстом.
2. Сервер генерирует сеансовый ключ AES-256, шифрует его публичным ключом клиента (`SIMPLEBLOB`) и отправляет клиенту.
3. Клиент расшифровывает его своим приватным ключом.
4. Далее все кадры: `IV (16 байт) || AES-256-CBC(PKCS#5)`. Для каждого сообщения выбирается новый случайный IV.

### Запрос (после расшифровки)

Одна строка UTF-8: `КОМАНДА[<TAB>аргумент1[<TAB>аргумент2]]`

| Команда | Аргументы | Данные |
|---|---|---|
| `GET_OS` | - | тип и версия ОС |
| `GET_TIME` | - | текущее время (UTC и местное) |
| `GET_UPTIME` | - | время с запуска ОС |
| `GET_MEMORY` | - | используемая память |
| `GET_DRIVES` | - | типы дисков и файловые системы |
| `GET_FREESPACE` | - | свободное место на локальных (fixed) дисках |
| `GET_ACL` | `FILE` или `REG`, путь | DACL файла/папки/ключа реестра |
| `GET_OWNER` | `FILE` или `REG`, путь | владелец объекта |

Пути реестра: `HKLM\...`, `HKCU\...`, `HKCR\...`, `HKU\...` (или `HKEY_LOCAL_MACHINE\...` и т.д.).
Для `HKCU` берётся профиль пользователя, от имени которого запущен агент.

### Ответ

Текст UTF-8, строки разделены `\n`. Каждая строка - **запись**:

```
ТЕГ <TAB> ключ=значение <TAB> ключ=значение ...
```

Ключи - `[a-z0-9_]+`. В значениях экранируются `\` -> `\\`, табуляция -> `\t`, перевод строки -> `\n`, `\r` -> `\r`.
Первая запись всегда `RESULT`:

```
RESULT  status=OK     command=GET_OS
RESULT  status=ERROR  code=5  source=win32     message=Отказано в доступе.
RESULT  status=ERROR  code=1  source=protocol  message=unknown command
```

Далее идут записи с данными:

| Тег | Поля |
|---|---|
| `OS` | name, product_name, display_version, major, minor, build, platform_id, service_pack, sp_major, sp_minor, product_type, arch, computer_name |
| `TIME` (две записи: `scope=utc` и `scope=local`) | iso, year, month, day, hour, minute, second, millisecond, day_of_week, unix; для local ещё utc_offset_minutes, tz_name |
| `UPTIME` | milliseconds, boot_time_utc, boot_time_unix |
| `MEMORY` | load_percent, total_phys, avail_phys, total_pagefile, avail_pagefile, total_virtual, avail_virtual (в байтах) |
| `DRIVE` (по записи на диск) | root, type (fixed/removable/network/cdrom/ramdisk/...), class (local/network/removable), fs, label, ready |
| `FREESPACE` (по записи на локальный диск) | root, total_bytes, free_bytes, free_to_user_bytes (или error) |
| `OWNER` | object_type, path, sid, name, name_use |
| `ACL` (заголовок) | object_type, path, null_dacl, dacl_protected, ace_count |
| `ACE` (по записи на каждую ACE) | index, sid, name, name_use, ace_type, ace_type_id, ace_flags, ace_flag_names, scope, mask, bits (номера через запятую), bit_names (названия через запятую) |

Названия битов в `bit_names` зависят от типа объекта: для файла `FILE_READ_DATA`, для папки `FILE_LIST_DIRECTORY`,
для раздела реестра `KEY_QUERY_VALUE` и т.д. (константы из MSDN).

Клиент в меню по клавише `r` показывает сырой ответ - удобно смотреть формат.

## Параллельная обработка на сервере

* Один порт завершения, `2 x число процессоров` рабочих потоков, все ждут в `GetQueuedCompletionStatus`.
* Приём подключений через `AcceptEx` (8 одновременных ожиданий).
* У каждого подключения одновременно висит ровно одна операция (приём или отправка), поэтому в обработчике завершения
  сокет и контекст закрываются без `CancelIo` + `PostQueuedCompletionStatus`.
* Бездействующие подключения (30 с) закрываются: сторожевой цикл в главном потоке вызывает `CancelIoEx`.
* Диагностика на консоль: подключение, отключение, принятый запрос, результат обработки.

## Ограничения

* Шифрование без имитовставки (MAC): конфиденциальность обеспечена, защиты от целенаправленной подмены шифртекста нет.
  Публичный ключ клиента не аутентифицируется (нет сертификатов), поэтому от активного MITM схема не защищает.
  Для учебной работы этого достаточно, в реальной системе добавляют HMAC и сертификаты.
* Сервер слушает только IPv4.
* Код проверен только на компилируемость (кросс-сборка x64/x86); на реальной Windows запускайте и проверяйте самостоятельно.
