# R1 — роутер-шлюз: вся NAT-конфигурация

**Подключение:** консольный кабель от **PC3** → порт CONSOLE R1.
**Порты:** F0/0 → R2 (публичная сеть), F0/1 → S1 Fa0/5 (LAN, шлюз 192.168.1.1).
Файл покрывает ВСЁ, что вводится на R1: сброс → Часть 1 (база) → Часть 2 (NAT) → Часть 3 (PAT) → Часть 4 (Static NAT).

> Блоки команд можно вставлять в консоль целиком — строки с `!` IOS игнорирует.
> Раздел «Сброс» интерактивный: вставлять нельзя, отвечать руками.

## 0. Сброс роутера

```
enable
write erase
```
- `Erasing the nvram filesystem will remove all configuration files! Continue? [confirm]` → **Enter**
```
reload
```
- `System configuration has been modified. Save? [yes/no]` → **no**  ← иначе сброс отменится!
- `Proceed with reload? [confirm]` → **Enter**
- после загрузки: `Would you like to enter the initial configuration dialog? [yes/no]` → **no**
- если спросит `Would you like to terminate autoinstall? [yes]` → **Enter**

Проверка чистоты:
```
show startup-config      ← конфига нет
show ip interface brief  ← всё unassigned / administratively down
```

## 1. Часть 1 — базовая настройка

```
configure terminal
hostname R1
no ip domain-lookup
enable secret class
line console 0
 password cisco
 login
line vty 0 4
 password cisco
 login
exit
service password-encryption
banner motd #Authorized Users Only!#
interface f0/0
 ip address 209.165.200.230 255.255.255.248
 no shutdown
interface f0/1
 ip address 192.168.1.1 255.255.255.0
 no shutdown
exit
ip route 0.0.0.0 0.0.0.0 209.165.200.225
end
copy running-config startup-config
```
- `no ip domain-lookup` — чтобы опечатки не «зависали» на минуту.
- `enable secret class` — пароль привилегированного режима; `cisco` — консоль и VTY; `service password-encryption` — шифрует их в конфиге.
- `ip route 0.0.0.0 0.0.0.0 209.165.200.225` — маршрут по умолчанию в сторону R2 (шаг i методички).

Проверка:
```
show ip interface brief   ← f0/0 и f0/1 up/up с нужными IP
show ip route             ← есть строка S* 0.0.0.0/0 via 209.165.200.225
```

## 2. Часть 2 — динамический NAT (пул из ТРЁХ адресов)

```
configure terminal
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat pool PUBLIC_ACCESS 209.165.200.226 209.165.200.228 netmask 255.255.255.248
ip nat inside source list 1 pool PUBLIC_ACCESS
interface f0/1
 ip nat inside
interface f0/0
 ip nat outside
end
```
- `access-list 1` — кто допущен к трансляции (вся LAN); `0.0.0.255` — wildcard-маска, НЕ 255.255.255.0.
- пул `.226–.228` — три публичных адреса; `netmask` — реальная маска подсети.
- `ip nat inside source list 1 pool PUBLIC_ACCESS` — связка ACL+пул; слово `inside` обязательно; имя пула регистрозависимо.
- `ip nat inside` / `ip nat outside` — метки интерфейсов, без них NAT не работает.

### Тесты Части 2 (пингуют остальные, ты смотришь таблицу)
Порядок: **PC4** (с PC-B) → **PC3** (с PC-A) → **PC1** (со S1) → **PC2** (со S2 — должно провалиться).

После каждого пинга:
```
show ip nat translations
```
Ожидаемо:
- 192.168.1.3 (PC4) → 209.165.200.226
- 192.168.1.2 (PC3) → 209.165.200.227
- 192.168.1.11 (S1) → 209.165.200.228
- пинг со S2 (PC2) проваливается — пул исчерпан. В консоли R1 может появиться `%NAT-6-ADDR_ALLOC_FAILURE: ... pool may be exhausted` (на IOS 12.4 текст может отличаться). Это ОЖИДАЕМЫЙ результат лабы, не ошибка.

Дополнительно:
```
show ip nat translations verbose   ← таймаут 24 часа (NAT «один к одному»)
show ip nat statistics
```

### Очистка перед Частью 3 (в priv EXEC)
```
clear ip nat translations *
clear ip nat statistics
```

## 3. Часть 3 — PAT

### 3.1 PAT в тот же пул (шаги 1–3)
ACL, пул и метки интерфейсов остаются; меняется одна команда — добавляется `overload`:
```
configure terminal
no ip nat inside source list 1 pool PUBLIC_ACCESS
ip nat inside source list 1 pool PUBLIC_ACCESS overload
end
```
Тесты:
- PC4 `ping 209.165.200.1` → `show ip nat translations`: одна запись с портом `icmp 209.165.200.226:1 192.168.1.3:1 ...` (строк `--- ... ---` больше нет).
- `show ip nat translations verbose` → таймаут теперь **1 минута**.
- Массовый тест: PC3 и PC4 `ping -t 209.165.200.1` → у обоих inside global = .226, различие — порты.

После: остановить пинги (Ctrl+C на ПК), затем:
```
clear ip nat translations *
clear ip nat statistics
```

### 3.2 PAT на внешний интерфейс (шаги 4–6)
```
configure terminal
no ip nat inside source list 1 pool PUBLIC_ACCESS overload
no ip nat pool PUBLIC_ACCESS
ip nat inside source list 1 interface f0/0 overload
end
```
(если `no ip nat pool` ругается «in use» — сначала `clear ip nat translations *` и повтори)

Тесты:
- PC4 ping → inside global теперь **209.165.200.230** (адрес F0/0 самого R1).
- Массовый: PC3/PC4 `ping -t`, PC1/PC2 `ping 209.165.200.1 repeat 2000` → `show ip nat translations`: 4 записи, все через .230 с разными портами. Потом всех остановить (Ctrl+C / пинг сам закончится).

## 4. Часть 4 — статический NAT

PC-A (PC3, 192.168.1.2) станет доступен «из интернета» по адресу 209.165.200.229. PAT-на-интерфейс из 3.2 остаётся работать.

```
clear ip nat translations *
clear ip nat statistics
configure terminal
ip nat inside source static 192.168.1.2 209.165.200.229
end
show ip nat translations
```
→ статическая запись `--- 209.165.200.229  192.168.1.2  ---` видна сразу, без трафика.

Тест: **PC4** на консоли R2 выполняет `ping 209.165.200.229` — должно проходить (на PC3 должен быть разрешён ICMP в брандмауэре). После этого снова:
```
show ip nat translations
```
→ добавится запись с портами (`icmp 209.165.200.229:x  192.168.1.2:x  209.165.200.225:x ...`) — доказательство, что входящие дошли до PC3.

## 5. Финал

```
show running-config
```
Чек-лист конфига: `access-list 1 permit 192.168.1.0 0.0.0.255`; `ip nat inside source list 1 interface f0/0 overload`; `ip nat inside source static 192.168.1.2 209.165.200.229`; `ip nat inside` на f0/1 и `ip nat outside` на f0/0; default route. Пула в конце быть НЕ должно — мы его удалили.

```
copy running-config startup-config
```

## Диагностика: все пинги падают, `show ip nat translations` пустой

Значит, на R1 нет рабочей связки NAT. Проверь:
```
show running-config | include ip nat|access-list
show ip nat statistics
show ip interface brief
```
В конфиге для Части 2 должны быть ВСЕ строки:
```
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat pool PUBLIC_ACCESS 209.165.200.226 209.165.200.228 netmask 255.255.255.248
ip nat inside source list 1 pool PUBLIC_ACCESS
```
и в `show ip nat statistics` — `Inside interfaces: FastEthernet0/1`, `Outside interfaces: FastEthernet0/0`.

Типичные причины:
1. Начата Часть 3: `no ip nat inside source list 1 pool PUBLIC_ACCESS` введена, а `... overload` ещё нет — между ними пинговать не может никто. Доведи до `ip nat inside source list 1 pool PUBLIC_ACCESS overload`.
2. Опечатка интерфейса из методички: `g0/0/0` вместо вашего `f0/0` — команда отклоняется, NAT не создаётся.
3. Случайно удалён ACL, пул или метки `ip nat inside/outside` — верни из раздела 2.

Восстановление Части 2 (добавь только недостающее):
```
configure terminal
ip nat inside source list 1 pool PUBLIC_ACCESS
end
clear ip nat translations *
```
Проверка: PC4 `ping 209.165.200.1` → `show ip nat translations` должна показать `192.168.1.3 → 209.165.200.226`.

Если PC3/PC4 пингуются, а S1/S2 нет — на свичах нет шлюза:
```
show run | include default-gateway   ← должно быть ip default-gateway 192.168.1.1
ping 192.168.1.1
```
Про R2: `ping 209.165.200.1` с R2 — пинг его собственного Loopback (всегда работает, ничего не тестирует). С R2 тестируется только `ping 209.165.200.229` в Части 4. Пинги с R2 в 192.168.1.x не работают и не должны — у R2 нет маршрута в LAN, снаружи LAN видна только через NAT.

## Ответы на вопросы лабы (для отчёта)
- **Часть 2a:** inside local PC-B `192.168.1.3` транслирован в **209.165.200.226**; тип адреса — **inside global** (публичный, из NAT-пула).
- **Часть 3:** PC-B тоже → **209.165.200.226** (inside global). Отличие от NAT: нет «простых» записей `---`; записи привязаны к портам (`icmp ...:1`); таймаут 1 минута вместо 24 часов.
- **Как роутер различает потоки при PAT:** по уникальным номерам портов в inside global адресе — таблица NAT хранит пару «публичный IP:порт ↔ внутренний IP:порт».
